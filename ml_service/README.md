## Зачем здесь ML, если ТЗ его не требует

Это первое, что стоит проговорить честно — и это же главный аргумент защиты.

ТЗ **не требует** машинного обучения: п. 2.7.5 прямо выносит «обязательное применение
искусственного интеллекта, машинного обучения, технологий больших данных или облачной
инфраструктуры» за границы обязательного решения. Основной игровой цикл работает
офлайн, на устройстве, без сервера (п. 3.1.5).

Поэтому платформа построена так, чтобы **не подменять обязательную механику**, а
закрывать те требования, которые возникают, *если* команда идёт дальше минимума.
П. 3.2 ставит три условия — каждое выполнено буквально:

| Условие ТЗ §3.2 | Как выполнено |
|:---|:---|
| «какую задачу решают» | Три модели, у каждой карточка в [`docs/ml-cards/`](docs/ml-cards/) с задачей, границами и запретами |
| «какие данные обрабатывают» | Только синтетическая телеметрия. Персональные данные не собираются — запрет [проверяется кодом](src/monetka/common/events.py) и падает в CI |
| «как контролируется корректность» | Гейты качества, детерминированный fallback, дрейф-мониторинг, проверка паритета экспорта |
| «OpenAPI + запуск одной процедурой» | [`docker-compose.yml`](docker-compose.yml), OpenAPI на `/docs`, запуск `make up` |

> ### ⬥ Главное ограничение
> **Ни одна модель не может изменить баланс, заблокировать покупку, повлиять на
> настроение котика или на срок достижения цели.**
>
> Вся игровая экономика детерминирована и живёт на устройстве. Модель выбирает
> **только текст подсказки** и **порядок заданий**. Это не обещание в документе —
> это закодировано в контрактах и проверено состязательными тестами, где модели
> подают заведомо вредные оценки и убеждаются, что правила устояли.
>
> Обоснование — [ADR 0001](docs/adr/0001-ml-may-not-touch-the-economy.md).

## Куда это подключается в приложении

Приложение — Flutter, четыре раздела. Платформа входит ровно в один.

| Раздел | Что даёт платформа | Модель? |
|:---|:---|:---:|
| **Советник** | Текст подсказки по итогам периода | ✅ выбирает формулировку |
| **Советник** | Какое задание предложить следующим | ✅ тай-брейкер внутри правила |
| **Цели** | Срок достижения цели | ❌ формула ТЗ §2.5.7 |
| **Магазин** | Цены, категории, влияние на котика | ❌ [YAML-контент](content/catalog_items.yaml) |
| **Мяу** | Настроение и стадия котика | ❌ [правила](content/pet_rules.yaml) |

Подробно, с кодом на Dart — [`app-integration/`](app-integration/).

**Почему настроение котика — формула, а не модель.** Ребёнок должен понимать,
*почему* котик загрустил: «не купил еду — котик голодный». Если настроение выдаёт
модель, этот ответ исчезает, а вместе с ним и обучающий эффект.

## Быстрый старт

### Без Docker, за две минуты

```bash
python -m venv .venv && .venv/Scripts/activate   # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev,transform]"
dbt deps --project-dir transform/dbt_monetka --profiles-dir transform/dbt_monetka
monetka demo
```

`monetka demo` прогоняет весь конвейер: генерация синтетической телеметрии → bronze →
silver → gold → проверки качества → обучение → экспорт в ONNX. Ничего, кроме Python,
не требуется. Ровно это же выполняет CI.

<sub>Проверено на Windows 10 и Python 3.12; `make` для этого пути не нужен.</sub>

```bash
monetka serve     # OpenAPI → http://localhost:8000/docs
```

### Полный стек

```bash
cp .env.template .env && make up
```

Redpanda, SeaweedFS, Iceberg REST catalog, Trino, Postgres, Airflow, MLflow, API, Grafana.
Адреса — в [`docs/runbook.md`](docs/runbook.md).

## Архитектура

```
Android / Flutter — офлайн, on-device
  │  телеметрия: выключена по умолчанию, включает взрослый
  │  инференс ONNX локально: ничего не уходит в сеть
  ▼
Redpanda  monetka.game.events.v1 ──► DLQ
  ▼
BRONZE   append-only · дедуп по event_id · отвергнутое сохраняется
  ▼
SILVER   типизированные факты · починка порядка событий
  ▼
GOLD     7 витрин · dbt · Iceberg/SeaweedFS · Trino
  ├──► обучение → гейты → MLflow → ONNX → обратно в приложение
  ├──► дрейф признаков (PSI)
  ├──► Grafana · раздел взрослого
  └──► мониторинг модели ◄── hint_shown ◄── приложение
       (замкнутая петля: что модель сделала в проде)
```

**Петля замкнута.** Приложение возвращает событие `hint_shown` — журнал
предсказаний. Из него собирается `mart_model_performance`, и `monetka monitor`
отвечает на два разных вопроса: исправна ли выкладка (метки не нужны, ловит
сломанный релиз) и меняет ли персонализация поведение (сравнение со случайно
назначенной контрольной группой).

Оркестрация — Airflow. Подробно: [`docs/architecture.md`](docs/architecture.md).

## Модели

| Модель | Задача | Что **запрещено** |
|:---|:---|:---|
| `behaviour_segment` | Определить паттерн периода, чтобы подобрать подсказку | Менять баланс, блокировать покупку, влиять на котика |
| `quest_recommender` | Выбрать следующее задание по слабейшей компетенции | Превышать возрастную сложность, нарушать покрытие трёх тем |
| `economy_anomaly` | Найти разбалансировку игровой экономики | Показываться ребёнку вообще — это инструмент методиста |

**Три находки, которые стоит знать**

<table>
<tr><td width="33%" valign="top">

**Архетипы сходятся**

Точность падает с 0.894 (период 3) до 0.542 (период 12): по мере обучения «транжира»
начинает вести себя как «планировщик».

Это не дефект модели — это работающее обучение. Модель ограничена горизонтом
раннего распознавания и **отказывается отвечать** за ним.

</td><td width="33%" valign="top">

**Паритет ONNX и float32**

Регрессор обучался на float64, а телефон считает на float32 — пороги бинов
расходились, и 4.2% строк уходили не в ту ветку сразу во многих деревьях.

Обучение на float32 устранило это полностью: **ранговая корреляция 1.0**.

</td><td width="33%" valign="top">

**Порядок импорта**

`onnxruntime` до `skl2onnx` роняет интерпретатор access violation'ом без traceback.

Порядок зафиксирован и защищён тестом, иначе это «почистят» и экспорт умрёт
беззвучно.

</td></tr>
</table>

**Fallback обязателен.** Если модель недоступна или ответила дольше 50 мс — показывается
детерминированная подсказка по правилам. Ребёнок разницы не замечает. Отсутствие модели
никогда не ломает игровой цикл.

**Измерение пользы — отдельная карточка.** [`hint_effectiveness.md`](docs/ml-cards/hint_effectiveness.md)
разбирает две ловушки, на первую из которых я наступил: сравнение по факту
срабатывания модели вместо случайно назначенной когорты даёт уверенный
неверный ответ «модель вредит».

## Приватность

Требование ТЗ §3.5 — обязательный сценарий работает без аккаунта и без сбора
персональных данных. Реализовано тремя независимыми механизмами:

1. **Нет свободного текста.** Игровое имя ребёнка и имя котика не покидают устройство.
   В телеметрию идут только коды из закрытых словарей.
2. **Псевдонимный сбрасываемый идентификатор.** Случайный UUIDv4, созданный на
   устройстве и уничтожаемый при сбросе профиля. Не выводится из железа или аккаунта.
3. **Запрет на уровне кода.** [`assert_no_personal_data`](src/monetka/common/events.py)
   отклоняет событие с подозрительным именем поля — в генераторе, в приёмнике и в CI.
   Плюс аудит **всех 360 колонок** хранилища на чтении.

Телеметрия **выключена по умолчанию**. Весь обязательный цикл работоспособен при
выключенной телеметрии. Секретов в репозитории нет: `.env` в `.gitignore`,
gitleaks по всей истории в CI.

Подробно — [`docs/privacy.md`](docs/privacy.md).

## Проверяемость

Каждое нетривиальное утверждение в документации воспроизводится командой:

```bash
monetka diagnose behaviour-horizon   # таблица падения точности
monetka diagnose quest-ranking       # ранговая корреляция
monetka quality                                      # минимумы ТЗ §2.6 по данным
monetka monitor                                      # здоровье модели + сравнение групп
monetka contracts --check                            # схемы не разошлись с моделями
```

Набор тест-кейсов с привязкой к исполняемым тестам — [`docs/test-cases.md`](docs/test-cases.md).

Минимумы ТЗ §2.6 доказываются **по фактическим данным**, а не по декларации в файле:
27 комбинаций котика, 12 периодов, 9 заданий, 14 позиций каталога, 5 целей, 4 стадии.

Матрица соответствия — [`docs/compliance-tz.md`](docs/compliance-tz.md).

## Границы и честные ограничения

* Данные **синтетические**. Это осознанное решение: наблюдать реальных детей без
  согласия законных представителей нельзя (ТЗ §8.4), а офлайн-приложение такой
  поток и не отдаёт.
* Метрики моделей характеризуют **корректность конвейера**, а не педагогическую
  эффективность. Проверка на реальных данных возможна только после исследования
  с надлежащим согласием.
* Платформа **не входит** в обязательный конкурсный минимум и не заменяет ни одного
  обязательного требования ТЗ.

Полный перечень с планом развития — [`docs/limitations.md`](docs/limitations.md).
