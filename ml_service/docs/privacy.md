# Приватность и защита ребёнка

Требуется ТЗ §5.9 — «описание разрешений Android, состава собираемых данных и
процедуры удаления профиля». Основание — ТЗ §3.5.

## Исходная позиция

Обязательный сценарий работает **без аккаунта и без сбора персональных данных**
ребёнка или родителя (ТЗ §3.5). Телеметрия **выключена по умолчанию** и
включается только взрослым в защищённом разделе.

Весь игровой цикл полностью функционален при выключенной телеметрии. Это не
деградация — это штатный режим.

## Что собирается, если взрослый включил телеметрию

| Поле | Что это | Почему не персональные данные |
|---|---|---|
| `profile_pseudo_id` | Случайный UUIDv4 | Генерируется на устройстве, не выводится из железа, аккаунта или номера; уничтожается при сбросе профиля |
| `session_id` | Случайный UUIDv4 | Живёт в пределах одного запуска |
| `occurred_at` | Время события, UTC | Игровое время, не геопривязка |
| `app_version`, `android_api_level` | Версия сборки и API | Техническая среда |
| `period_no` | Номер игрового периода | Порядковый номер, не дата |
| `demo_mode` | Флаг демо-режима | Технический |
| payload | Игровые числа: суммы, коды позиций, исходы | Значения из закрытых словарей и целые числа |

## Чего не собирается — и не может быть собрано

* **Игровое имя ребёнка и имя питомца.** Ни одно событие не содержит свободного
  текста. В телеметрию идут только коды внешнего вида из закрытых перечислений.
* Возраст, дата рождения, пол.
* Телефон, e-mail, адрес, геолокация.
* Идентификаторы устройства: IMEI, Android ID, рекламный идентификатор.
* Контакты, фотографии, содержимое экрана.
* Любые реальные финансовые сведения. Валюта только игровая и не имеет реальной
  стоимости.

## Как запрет обеспечен технически

Три независимых механизма — так что ошибка одного не приводит к утечке:

**1. Запрет на уровне контракта.** Функция `assert_no_personal_data` отклоняет
событие, если имя поля похоже на персональные данные. Выполняется при создании
события, при загрузке в bronze и в CI.
[`events.py`](../src/monetka/common/events.py)

Проверка токенная, а не подстрочная: подстрочная ловила бы `cumulative` и
`volatility` из-за `lat`, а проверка, которая кричит без повода, быстро
отключается.

**2. Аудит на чтении.** Проверка `no_personal_data_columns` обходит **каждую
колонку** в bronze, silver, gold и ml. Покрывает таблицы, созданные не через
контракт — dbt-моделью или руками.

**3. Тесты.** `test_personal_data_fields_are_rejected` перечисляет конкретные
запрещённые поля; `test_safe_fields_are_not_flagged` защищает от ложных
срабатываний; `test_no_personal_data_columns_anywhere` прогоняет аудит по
реальному хранилищу.

## Разрешения Android

Обязательный сценарий не требует **ни одного** опасного разрешения.

| Разрешение | Нужно? |
|---|---|
| CAMERA, RECORD_AUDIO | Нет |
| ACCESS_*_LOCATION | Нет |
| READ_CONTACTS | Нет |
| BLUETOOTH, NEARBY_DEVICES | Нет |
| READ/WRITE_EXTERNAL_STORAGE | Нет — данные в приватном хранилище приложения |
| INTERNET | Только если взрослый включил телеметрию; игровой цикл без него полон |

## Удаление профиля

Взрослый в защищённом разделе может сбросить или удалить локальный профиль
(ТЗ §3.5, §2.5.12). Процедура:

1. Локальные данные приложения удаляются.
2. `profile_pseudo_id` уничтожается. Новый профиль получает новый случайный
   идентификатор, никак не связанный с предыдущим.
3. Ранее отправленная телеметрия остаётся связанной с уничтоженным
   идентификатором, восстановить связь с человеком по ней невозможно — она и не
   существовала: идентификатор ни к чему не привязан.

Обращение к разработчику не требуется.

## Если команда всё же решит обрабатывать персональные данные

ТЗ §3.5 допускает это при условии, что команда обоснует необходимость, опишет
состав, цель, срок хранения, удаление и правовое основание, и предусмотрит
технический алгоритм получения согласия — подписываемого законным
представителем ребёнка.

**Текущая реализация этой ветки не использует и в ней не нуждается.** Если она
понадобится, это отдельное проектное решение с юридическим сопровождением, а не
изменение конфигурации.

## Что запрещено в самом приложении (ТЗ §3.5)

Платформа этого не нарушает и нарушить не может — соответствующих контрактов
просто нет:

* реклама, платные подписки, внутриигровые покупки;
* механики случайной платной награды;
* внешние ссылки, доступные ребёнку без раздела взрослого;
* тексты, которые запугивают или стыдят — проверяется тестом
  `test_no_shaming_or_frightening_language` по всем текстам контента;
* ощущение, что забота о живом существе зависит от реальной оплаты.
