# Интеграция с приложением

Приложение — **Flutter** (`mobile_app/` в ветке `frontend`), четыре раздела:
**Цели**, **Советник**, **Магазин**, **Мяу**.

Платформа подключается ровно в одной точке — **Советник**. Остальные три раздела
работают на детерминированной логике и не зависят от моделей вообще.

> ⚠️ Код в [`lib/monetka_advisor.dart`](lib/monetka_advisor.dart) **не
> собирался**: Flutter SDK на машине, где готовилась платформа, отсутствует.
> Это контракт и референсная реализация, а не проверенный сборкой модуль.
> Первый прогон `flutter analyze` наверняка потребует правок по именам API
> пакета `onnxruntime`.

## Что куда ложится

| Раздел приложения | Что даёт платформа | Модель участвует? |
|---|---|---|
| **Советник** | Текст подсказки по итогам периода | Да — выбирает формулировку |
| **Советник** | Какое задание предложить следующим | Как тай-брейкер внутри правила |
| **Цели** | Срок достижения цели | **Нет.** Формула ТЗ §2.5.7 |
| **Магазин** | Цены, категории, влияние на котика | **Нет.** [`content/catalog_items.yaml`](../content/catalog_items.yaml) |
| **Мяу** | Настроение и стадия котика | **Нет.** [`content/pet_rules.yaml`](../content/pet_rules.yaml) |
| Раздел взрослого | Агрегаты прогресса | Нет, витрина `mart_competency_coverage` |

Почему так узко — [ADR 0001](../docs/adr/0001-ml-may-not-touch-the-economy.md).
Коротко: ТЗ §2.7.5 выносит ML за границы обязательного решения, а §2.2 требует
объяснимости. Модель, которая меняет баланс или настроение котика, ломает связь
«моё решение → последствие», ради которой приложение и делается.

## Настроение котика — почему это правила, а не модель

Идея «пусть настроение меняется от метрик» реализована — и намеренно **формулой**:

```yaml
# content/pet_rules.yaml
decay_per_period:  { satiety: 30, energy: 20, tidiness: 15, mood: 10 }
floor_value: 10          # ниже не опускается никогда
stages:
  no_regression: true    # стадия не понижается ни при каких решениях
```

Ребёнок должен понимать, **почему** котик загрустил: «не купил еду — котик
голодный». Если настроение выдаёт модель, этот ответ исчезает, а вместе с ним и
обучающий эффект. Плюс ТЗ прямо запрещает необратимые негативные последствия от
ошибки пользователя — поэтому пол по каждому состоянию и запрет на понижение
стадии.

## Подключение

**1. Положить артефакты в assets**

```bash
# в репозитории платформы
monetka demo            # или monetka train && monetka export
cp artifacts/models/behaviour_segment.onnx  <app>/assets/models/
cp artifacts/models/behaviour_segment.json  <app>/assets/models/
```

**2. pubspec.yaml**

```yaml
dependencies:
  onnxruntime: ^1.4.1

flutter:
  assets:
    - assets/models/behaviour_segment.onnx
    - assets/models/behaviour_segment.json
```

**3. Загрузить один раз при старте**

```dart
final model = await BehaviourSegmentModel.loadOrNull();  // null — это норма
final advisor = Advisor(model);
```

**4. Показать подсказку**

```dart
final hint = advisor.hintFor(snapshot);
// hint.text     — что произошло
// hint.nextStep — что делать дальше
// hint.source   — 'rule' или 'model'
```

## Три правила, которые нельзя нарушать

**Порядок признаков.** ONNX принимает безымянный тензор. Собрали вектор в другом
порядке — модель вернёт уверенный бессмысленный ответ, без единой ошибки.
Поэтому порядок берётся из `.json`-сайдкара и проверяется при сборке вектора.

**Отказ вне горизонта.** Модель обучена на периодах ≤ 6. Дальше архетипы
сходятся, и она отказывается отвечать. Горизонт лежит в сайдкаре
(`applicability.max_period_no`), а не зашит в приложение — переобучили с другим
горизонтом, приложение подхватило.

**Fallback обязателен.** Нет модели, не загрузилась, ответила медленно — показывается
подсказка по правилам. Ребёнок разницы не замечает. Это не аварийный режим: при
выключенной телеметрии и без единой модели приложение полностью функционально,
как и требует ТЗ §3.1.5.

## Телеметрия

Выключена по умолчанию. Включается **только взрослым** в защищённом разделе
(ТЗ §3.5). Формат события — [`events.py`](../src/monetka/common/events.py).

В телеметрию **не попадают** игровое имя ребёнка и имя котика: ни одно событие
не содержит свободного текста, только коды из закрытых словарей. Запрет
проверяется кодом, а не дисциплиной ревьюера.

## Если решите делать нативно на Kotlin

Контракт тот же, меняется только рантайм:
`implementation("com.microsoft.onnxruntime:onnxruntime-android:1.19.2")`.
Порядок признаков, отказ вне горизонта и fallback остаются обязательными.
